# Отчёт о выполненных работах — Schedbook

Страница отчёта для заказчика: работы по неделям каждого дополнительного
соглашения, что менялось и сколько времени заняло.

Ставок, стоимостей и сумм на странице нет — ни одной. Это проверяется перед
каждой публикацией, см. «Проверка перед push».

## Публикация

**Settings → Pages → Source → GitHub Actions.** Дальше каждый push в `develop`
пересобирает сайт: `.github/workflows/pages.yml` публикует содержимое `site/`.

Адрес: `https://antinlay.github.io/schedbook-client-report/`

> Pages на бесплатном тарифе открыт всем, у кого есть ссылка. Для этой страницы
> это допустимо: внутри только описания работ и время. `meta robots` стоит
> `noindex, nofollow`, чтобы страница не попадала в поиск, но это просьба к
> поисковикам, а не защита.

## Обновляется ли сам?

**Нет.** Страница статическая, данные вшиты внутрь HTML — это и делает её
самодостаточной: она открывается без сервера, без API и работает с телефона
в самолётном режиме.

Обновление — два шага:

```bash
python3 build.py      # source/report-data.json → site/index.html
git commit -am "Отчёт за неделю N" && git push
```

Push сам запускает workflow, через минуту страница обновлена. Ссылка не меняется.

### Как сделать автоматическим

Данные лежат в `source/report-data.json`. Чтобы страница обновлялась без
участия человека, нужно, чтобы этот файл обновлялся сам:

1. Apps Script (`sbBuildWeeklyReport_`) уже собирает недельные строки в реестре.
2. Добавить в него отправку JSON в этот репозиторий через GitHub API
   (`PUT /repos/antinlay/schedbook-client-report/contents/source/report-data.json`)
   с токеном в Script Properties.
3. Коммит в `develop` запустит workflow, и страница пересоберётся.

Тогда цепочка «работа → реестр → отчёт заказчику» замкнётся полностью.
Пока этот шаг не сделан, обновление ручное — две команды выше.

## Проверка перед push

Страница уходит заказчику, поэтому финансовых данных в ней быть не должно:

```bash
grep -c '₽' site/index.html          # должно быть 0
grep -ciE '\bруб|\bставка|стоимость' site/index.html   # должно быть 0
```

## Состав

| Путь | Что это |
| --- | --- |
| `site/index.html` | готовая страница, публикуется |
| `source/report.html` | исходник с данными внутри |
| `source/report-data.json` | данные: соглашения, недели, работы, время |
| `build.py` | оборачивает исходник в самостоятельный документ |

`build.py` добавляет `doctype`, `charset`, `viewport`, favicon и сброс стилей.
Без `charset` кириллица превращается в кракозябры, без `viewport` телефон рисует
страницу в десктопной ширине — заказчик смотрит с телефона, это критично.
